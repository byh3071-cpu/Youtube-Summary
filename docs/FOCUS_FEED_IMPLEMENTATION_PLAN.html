STEP 00

디자인 계약

참고 제품의 외형을 섞는 것이 아니라 각 제품이 가장 잘 해결하는 문제만 가져온다. 이 표가 이후 코드 리뷰의 기준이다.

영역기준Focus Feed 적용
전체 구조Apple여백, 정렬, 텍스트 계층, 조용한 사이드바
홈 영상YouTube16:9 썸네일, 2줄 제목, 채널·시간 메타
롱폼YouTube카드 탐색 → URL이 있는 상세 재생

AI 기능Focus Feed보라색 유지, 콘텐츠보다 한 단계 낮게

제 판단으로 보정할 3가지

  • 모바일 카드: 1열 기본, 393px 2열은 비교 실험.
  • 롱폼 상세: 모달보다 `/watch/[videoId]` 우선.
  • 숏폼 분류: UI 모드와 60초 규칙을 분리해 확장 가능하게.

화면을 바꾸기 전에 색·간격·타입·모션을 제한한다. 이 단계에서는 기능과 레이아웃을 바꾸지 않는다.

STEP 02

YouTube식 홈 카드

가장 먼저 체감되지만 위험은 낮다. 영상이 주인공이고 AI는 보조 행동이어야 한다.

2-1 · 본문

  • 16:9 썸네일과 우하단 길이
  • 제목 2줄 고정
  • 채널 아바타·채널명·업로드 시간
  • 외곽 카드 배경 제거

2-2 · 행동

  • 기본: 콘텐츠 정보만
  • hover: 라디오·북마크
  • 더보기: 상태·인사이트
  • AI 요약은 작은 보조 행동

2-3 · 밀도

  • 모바일 1열 기본
  • 태블릿 2~3열
  • 데스크톱 3~5열
  • 행 높이 오차 1px 이하
STEP 03

롱폼 ≠ 숏폼

현재 공용 `FeedReelView`를 역할별로 분리한다. 이 단계가 구조 변화 중 가장 크므로 세 배포 단위로 나눈다.

LongformFeedView

자동재생 없음 · 카드에서 상세로 이동

ShortformFeedView

숏폼만 세로 snap · 우측 액션 레일

3-1 · 롱폼 목록

61초 이상 정책을 유지하되 분류 함수를 독립시킨다.

3-2 · `/watch/[videoId]`

영상, 제목·채널, 핵심 행동, AI 요약, 관련 영상. 뒤로 가기 시 목록 위치 복원.

3-3 · 숏폼

9:16, 오른쪽 행동, 하단 문맥, safe area. 기존 Reel 코드를 숏폼 전용으로 축소.

STEP 04

Spotify식 라디오

색을 복제하지 않고 지속 재생과 정보 계층을 가져온다. 플레이어 인스턴스는 UI 전환과 분리한다.

썸네일 · 제목 · 채널이전 · 재생 · 다음
진행률요약 · 큐 · 볼륨 · 확장

4-1 · 하단 바

데스크톱 3구역, 모바일 한 줄 미니 플레이어.

4-2 · 큐 패널

현재 재생 강조, 재정렬, 제거, 전체 비우기, 다음 항목.

4-3/4 · 확장·상태

영상·요약·큐 2열. 미니↔확장 전환 시 재생 인스턴스 유지.

STEP 05

Apple식 앱 셸

콘텐츠와 플레이어가 안정된 뒤 전체 공간을 정돈한다. 셸을 먼저 바꾸면 모든 화면의 회귀 범위가 커진다.

Navigation

사이드바 너비·그룹·활성 표현 통일, 모바일 하단 탐색 비교.

Layout

페이지 최대 너비, sticky 검색 범위, 읽기 순서와 정렬 기준.

Functional layer

glass는 검색·플레이어에만. 콘텐츠 surface에는 사용하지 않는다.

STEP 06

마지막 폴리시

정상 화면만 예쁜 제품이 되지 않도록 로딩·오류·입력 방식과 모든 화면 크기를 검증한다.

상태
