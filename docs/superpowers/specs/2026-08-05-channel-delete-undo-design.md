# 채널 삭제 실행 취소 UX 설계

## 문제

현재 채널 삭제는 `DELETE /api/custom-sources` 응답이 끝날 때까지 목록을 그대로 두고, 성공 여부를 표시하지 않은 채 `router.refresh()`만 호출한다. HTTP 오류도 확인하지 않아 사용자는 약 10초 동안 삭제가 시작됐는지, 성공했는지 알 수 없다.

## 목표

- 모바일과 PC에서 삭제 버튼을 누른 즉시 채널 행을 숨긴다.
- 실제 서버 삭제 전 5초 동안 실행 취소 기회를 제공한다.
- 서버 처리 중·성공·실패 상태를 명확히 보여준다.
- 실패하거나 12초 안에 응답하지 않으면 채널을 자동 복원한다.
- 기존 쿠키·Supabase 삭제 및 삭제 부활 방지 로직은 변경하지 않는다.

## 범위 밖

- 여러 채널 일괄 삭제
- 휴지통 또는 삭제 이력 화면
- API 스키마와 데이터베이스 구조 변경
- 채널 추가 흐름 개편

## 사용자 흐름

1. 사용자가 휴지통 버튼을 누른다.
2. 해당 채널 행은 즉시 목록에서 사라진다.
3. 화면 하단에 `채널을 삭제할 예정이에요`와 `실행 취소` 버튼을 5초 동안 표시한다.
4. 5초 안에 실행 취소하면 타이머를 취소하고 행을 즉시 복원한다. 서버 요청은 보내지 않는다.
5. 5초가 지나면 알림을 `채널을 삭제하는 중이에요`로 바꾸고 실제 DELETE 요청을 보낸다.
6. 성공하면 `채널을 삭제했어요`를 2초 동안 표시하고 `router.refresh()`로 서버 목록과 동기화한다.
7. 실패·비정상 HTTP 응답·12초 타임아웃이면 행을 복원하고 `삭제하지 못했어요 · 다시 시도`를 표시한다.

한 번에 하나의 삭제만 진행한다. 실행 취소 또는 서버 처리가 끝날 때까지 다른 삭제 버튼은 비활성화해 중복 요청과 여러 타이머 경쟁을 막는다.

## 컴포넌트와 상태

`ChannelRemovalProvider`를 `AppLayout`에 배치하고 현재 YouTube source ID 목록을 prop으로 전달해 PC 사이드바와 모바일 드로어가 같은 삭제 상태를 공유한다.

Provider는 다음 상태를 가진다.

- 숨길 채널 ID
- 대상 채널의 이름과 원본 데이터
- `undo`·`deleting`·`success`·`error` 단계
- 5초 커밋 타이머와 12초 요청 타임아웃

`YouTubeSourceList`는 Provider의 숨김 ID를 기준으로 항목을 필터링하고, 휴지통 클릭을 Provider에 위임한다. DELETE 성공 뒤에는 현재 서버 source ID 목록에서 대상이 사라질 때까지 숨김 상태를 유지한 후 정리한다. 따라서 느린 `router.refresh()` 중에도 삭제한 채널이 다시 깜박이지 않고, 나중에 같은 채널을 다시 추가할 수 있다.

## 알림 배치와 접근성

- 모바일: 라디오 플레이어와 `env(safe-area-inset-bottom)` 위에 고정한다.
- PC: 오른쪽 아래에 고정하되 라디오 플레이어보다 위에 둔다.
- 알림은 `role="status"`, `aria-live="polite"`를 사용한다.
- 실행 취소와 다시 시도 버튼은 최소 44×44px 터치 영역과 키보드 포커스 스타일을 제공한다.
- 삭제 처리 중인 버튼은 `disabled`와 `aria-busy`로 중복 입력을 막는다.
- 모바일 드로어를 닫아도 Provider가 유지되어 타이머와 알림이 계속 동작한다.

## 오류 처리

- `response.ok`를 확인하고 서버 오류 메시지가 있으면 사용한다.
- 네트워크 오류와 AbortController 타임아웃을 동일한 복원 경로로 처리한다.
- 실패 시 숨김 상태를 먼저 해제한 뒤 오류 알림을 보여 목록과 메시지가 모순되지 않게 한다.
- 오류 알림은 사용자가 닫거나 다시 시도할 때까지 유지한다.
- 다시 시도는 같은 채널을 즉시 다시 5초 실행 취소 단계에 넣는다.

## 검증

Playwright에서 다음을 확인한다.

- 모바일: 삭제 직후 행이 사라지고, 실행 취소하면 요청 없이 복원된다.
- PC: 5초 뒤 DELETE가 전송되고 처리 중 상태가 보인다.
- 서버 성공: 행이 계속 숨겨지고 목록이 갱신된다.
- 서버 실패·타임아웃: 행이 복원되고 다시 시도 안내가 보인다.
- 모바일과 PC 모두 알림이 뷰포트 및 라디오 플레이어와 겹치지 않는다.
- 실행 취소·다시 시도 버튼과 삭제 버튼의 터치 영역이 44px 이상이다.

## 완료 기준

- 삭제 버튼을 누른 뒤 100ms 안에 행과 상태 메시지가 바뀐다.
- 5초 실행 취소 중에는 DELETE 요청이 발생하지 않는다.
- 삭제 요청의 성공·실패가 사용자에게 항상 표시된다.
- 기존 채널 추가·동기화·삭제 부활 방지 테스트와 전체 모바일 UX 회귀가 통과한다.
