# 포커스피드 — 프로젝트 방향성 · 풀사이클 로드맵

> 살아있는 문서. 마일스톤 완료 시 갱신한다. 최신 세션 상태는 `docs/HANDOFF_*` 참조.
> 이 문서는 "이 프로젝트를 **왜, 어느 방향으로** 끌고 가는가"의 단일 기준점이다.
> (기존 `MASTER_STATUS_VISION.md`는 초기 제품 기능 비전이며 일부 stale — 본 문서가 상위.)

## 1. 정체성 · 문제 정의 · 프로젝트 성격

### 무엇인가
포커스피드는 **"흩어진 유튜브·RSS → 목표 기반 선별 → AI로 핵심만 소비 → 걸러낸 지식을 요한 브레인(PKM)에 적재"** 하는 개인 큐레이션·소비·지식화 파이프라인이다.

### 푸는 문제 (docs/PRD.md §2)
1. **소스 파편화** — 유튜브·뉴스를 앱마다 따로 본다 → 단일 병합 피드
2. **긴 영상 소비 부담** → 백그라운드 라디오 + 재생 중 AI 3줄 요약/인사이트
3. **관심사만 빠르게** → 키워드 필터·카테고리
4. **선택 피로 / 목표 정렬 부재** → 알고리즘 아닌 내 목표 문장 기준 큐레이션(`rankFeedByGoalsAction`, Gemini 랭킹)
5. **소비하고 끝나는 지식의 휘발** → reviewed 영상의 요약·인물·개념·관계를 요한 브레인 DB로 적재

### 이중성 (중요)
- **표면**: 개인·소규모 팀 SaaS (플랜 free/pro·팀·Stripe 결제·랜딩·요금제)
- **코어**: 요한 1인 PKM 도구 (`OWNER_EMAIL` = AI 무제한, `NOTION_WRITE_GRAPH` 기본 off의 개인 레이어)
- 실질은 **"1인용 PKM 코어를 SaaS 껍데기로 감싼" 형태**. 두 얼굴을 그대로 인정하고 간다.

### 요한 브레인과의 관계
포커스피드 = 요한 브레인(노션 기반 지식 중추)의 **"영상 입력 기관"**. 영상 → 트랜스크립트 → 요약 → 트리플/인물/개념을 브레인 DB에 **직접 upsert**(현재 구현 = **경로 A**, `src/app/actions/notion-sync.ts`, 게이트 기본 off). 코드·인프라는 독립이지만 지식 파이프라인상 브레인의 앞단(리뷰 게이트).

### 프로젝트 성격 (북극성의 전제)
- **도그푸딩 + 풀사이클 개발 학습장.** 요한이 실제로 쓰면서, 동시에 팀·요금제·결제·인프라를 미리 굴려보며 현업 전 사이클을 혼자 경험한다.
- **상업화·출시는 하지 않는다.** YouTube InnerTube(`youtubei.js`) 스크래핑이 ToS·저작권 리스크라, 개인/학습 용도로만. 상업화하려면 자막 소스 아키텍처 재설계(공식 API/콘텐츠 피벗) + 변호사 자문이 선행돼야 하는 **별개 대형 프로젝트**다.

## 2. 북극성 — 3축 균형

이 프로젝트의 목적은 세 축을 **한쪽 치우침 없이** 함께 전진시키는 것이다:

| 축 | 정의 | 성공의 모습 |
|---|---|---|
| **학습축** | 풀사이클 개발 커버리지 완성 | 안 해본 영역(관측성·분석·인프라·결제)을 의도적으로 다 경험 |
| **실사용축** | 매일 쓰는 도구 완성도 | "유용해서 실제로 쓴다"가 유지·강화됨 |
| **브레인축** | PKM 입력 파이프라인 | 영상→지식 적재가 신뢰성 있게 돌아감 |

**운영 원칙**: 모든 마일스톤은 세 축을 조금씩이라도 전진시킨다. "순수 학습을 위한 학습"(실사용·브레인과 무관한 기술 실험)은 지양한다. 학습 트랙을 실사용·브레인 니즈에 얹어서 배운다.

## 3. 개발 철학 (이미 확립 — 새 세션도 지킬 헌법)

레포 전반(`RULES.md`·`AI_COLLABORATION.md`·devlog·`docs/patterns/`)에서 일관되게 드러나는 원칙:

1. **실증 > 통과 선언.** VHK·게이트 PASS만으로 완료 선언 금지. "게이트 통과 ≠ 실사용 동작"을 반복 체득(프로덕션·실기기·로컬 DB 실증으로만 발견되는 버그가 있다).
2. **요청을 액면가로 구현하지 않는다.** 표면 증상 뒤의 의도를 먼저 판다. 핸드오프 지시조차 코드로 전제를 검증.
3. **보안·안전 최우선.** 순서 = 보안 → 안정성 → UX → 문서화. 파괴적·외부 영향 행위는 명시 승인제. 시크릿 위생.
4. **교훈 자산화.** 버그를 1회성으로 넘기지 않고 패턴(`PAT-*`)·devlog 교훈·회귀 테스트(tripwire)로 승격.
5. **AI 오케스트레이션 + 적대적 검증.** 다중 에이전트 역할 분담·핸드오프·생성/비평 분리(critic). AI 산출물조차 코드·실측으로 재검증.
6. **작업 격리.** 병렬 세션 충돌 방지를 위해 워크트리·브랜치 분리, 최신 origin/main에서 분기 → 검증 → rebase 머지 → 정리.

## 5. 풀사이클 학습 로드맵 (작은 배포 단위 백로그)

원칙: 각 단위는 **독립 실행·검증 가능한 PR급 크기**. 순서는 관측성(L1) 우선 — 최대 공백이자 실사용·브레인 양쪽에 다 쓰인다.

### L1 — 관측성/운영 (최우선)
| # | 단위 | 완료조건 | 학습목표 | 3축 기여 |
|---|---|---|---|---|
| L1-1 | 에러추적(Sentry) 연결 | 서버·클라 에러가 Sentry에 잡힘, 소스맵 연동 | 에러추적 셋업·이슈 트리아지 | 실사용(버그 조기발견)·브레인(sync 실패 관측) |
| L1-2 | 구조화 로깅(pino) | `console.*` → 구조화 로그, 요청 상관ID | 로깅 설계·상관관계 추적 | 학습·실사용 |
| L1-3 | 핵심 알림(Slack) | 결제 실패·Gemini auth 장애·5xx 급증 시 알림 | 알림 파이프라인·노이즈 관리 | 실사용·브레인 |
| L1-4 | 핵심 메트릭 대시보드 | 4지표(AI 호출량·비용·에러율·응답시간)가 실데이터로 대시보드에 표출(스크린샷 첨부) | 메트릭·대시보드 | 학습·실사용 |

### L2 — 결제·비즈니스 완성
| # | 단위 | 완료조건 | 학습목표 | 3축 기여 |
|---|---|---|---|---|
| L2-1 | Stripe 테스트모드 실 E2E | 결제→구독→갱신→해지→환불 플로우 실증 | 결제 라이프사이클 전체 | 학습·실사용 |
| L2-2 | `expires_at=null` 백필 | 기존 무기한 Pro 행 정리 + plan.ts 조임 | 데이터 마이그레이션·백필 | 학습(감사 [1-1 연장]) |
| L2-3 | 결제 실패 대사(reconciliation) | 실패/환불 시 상태 정합 + L1-3 알림 결합 | 결제 운영·대사 | 학습·실사용 |

### L3 — 분석·실험
| # | 단위 | 완료조건 | 학습목표 | 3축 기여 |
|---|---|---|---|---|
| L3-1 | 이벤트 계측 | 핵심 액션(요약·라디오·Q&A) 이벤트 수집 | product analytics | 실사용(행동 이해) |
| L3-2 | 퍼널 대시보드 | 방문→가입→사용 3단계 전환 수치가 대시보드에 표출 | 퍼널 분석 | 실사용 |
| L3-3 | 피처플래그 | 플래그로 기능 토글·점진 롤아웃 | 피처플래그 운영 | 학습·실사용 |
| L3-4 | A/B 실험 1건 | 가설→분리→통계 판정 1사이클 | 실험 설계·해석 | 학습 |

### L4 — 인프라·스케일 (트리거 도달 시)
| # | 단위 | 완료조건 | 학습목표 | 3축 기여 |
|---|---|---|---|---|
| L4-1 | 부하테스트(k6) 1건 | 핵심 경로 부하 프로파일 확보 | 성능·병목 측정 | 학습 |
| L4-2 | 분산 rate-limit(Upstash) | 인메모리 → 공유 저장소(감사 [1-3]) | 분산 상태·Redis | 학습·실사용 |
| L4-3 | `vercel.json`/cron 선언 | 크론·함수 설정 코드화 | IaC 감각 | 학습 |
| L4-4a | 테스트 커버리지 계측 | `vitest --coverage` 도입, 커버리지 % 리포트 출력 | 커버리지 측정 | 학습 |
| L4-4b | zod 도입 | mutation 라우트 핵심 N개(teams·bookmarks·custom-sources·playlists/save 등)에 zod 스키마 검증 | 선언적 검증 | 학습·(보안) |

## 6. 실사용 · 브레인 로드맵

학습축과 대칭이 되도록 실사용·브레인도 작은 단위·완료조건으로 둔다(3축 균형을 로드맵 구조에 실체화).

### 실사용(도그푸딩) — U 트랙
| # | 단위 | 완료조건 | 3축 기여 |
|---|---|---|---|
| U-1 | 큐레이션 방향 결정 | `recommendations.ts`(미배선) 살릴지/폐기 결정 문서화 + AI 랭킹 프롬프트 1차 개선 | 실사용 |
| U-2 | 팀·요금제 실사용 검증 | 팀 생성→초대→브리핑 실제 눌러 버그 목록화 + **[2-1] owner 락아웃 수정**(보안-우선 원칙에 따라 일정 부여) | 실사용·보안 |
| U-3 | 모바일/PWA 실기기 QA | `MOBILE_QA_CHECKLIST` 잔여 통과 | 실사용 |

### 브레인 파이프라인 — B 트랙
| # | 단위 | 완료조건 | 3축 기여 |
|---|---|---|---|
| B-1 | sync 신뢰성 | **[3-4] Innertube 영구캐시 수정**(실패 시 캐시 초기화) + sync 실패 L1-1 관측 결합 | 브레인 |
| B-2 | 적재 성숙 | 리뷰게이트→트리플/인물/개념 적재 품질 점검, 경로 A 유지 | 브레인 |
| B-3 | 문서 정합 | `YOHAN_BRAIN_EXPORT_MAPPING`(경로 B) 미채택 명시, `SYNC_HANDOFF`(경로 A) 정본화 | 브레인 |

## 7. 통합 마일스톤 (3축이 겹치는 단위로 묶기)

각 마일스톤은 세 축을 함께 전진시킨다. 예시 묶음:

- **M11 · 관측 가능한 제품** = L1-1 에러추적(학습) + L1-3 결제/AI 알림(실사용) + B-1 브레인 sync 신뢰성([3-4] 수정+관측)(브레인)
- **M12 · 결제 라이프사이클 완주** = L2-1 실 E2E + L2-2 백필 + L2-3 대사(+L1-3 알림)
- **M13 · 데이터로 보는 제품** = L1-4 메트릭 + L3-1 계측 + L3-2 퍼널
- **M14 · 실험 체계** = L3-3 플래그 + L3-4 A/B
- **M15 · 스케일 준비** = L4 전체 (트리거 도달 시)

(다른 세션 UI 리디자인 완료 = M11 착수의 선행 — 그 위에 얹는다.)

## 8. 안 할 것 / 트리거

### 지금 하지 않는다
- **상업화·출시** — YouTube 스크래핑 재설계 + 법률 검토 전 금지
- **유저 0에 스케일 인프라 조기 도입** — L4는 트래픽 트리거 전 대기(over-engineering 회피)
- **경로 B(inbox 패키지) 브레인 통합** — 현재 경로 A로 충분, 장기 수렴 목표

### "언제 움직여라" 트리거
| 신호 | 발동 |
|---|---|
| 무료 유저 가입 + 하루 AI 호출 수백 | L4-2 분산 rate-limit |
